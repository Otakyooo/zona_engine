## Текстурный конвейер ZONA

Мир рисовался плоскими цветами вершин — текстуры не привязывались нигде. Сделано за 7 коммитов (81f5106..4a018f6):

- **Мипмапы**: `zn_assets::generate_mips` вместо nearest-neighbour использует box-фильтр 2×2 с диапазонами `x*w/nw..(x+1)*w/nw` — нечётные размеры не теряют столбцы. Тесты на длину цепочки и сохранение среднего.
- **Текстуры**: бинарь `zn-gentex` (периодический value-noise, бесшовность по построению) генерирует 6 PNG 512² в `assets/textures/` — concrete, metal, rust, dirt, grass, wood, 1.3 МБ. Детерминирован, seed на материал.
- **Формат сцены**: `SceneNodeFile` получил `texture: Option<String>` и `uv_scale` (метры на тайл), оба `serde(default)` — старые сцены грузятся. Тест парсит `maps/arena.ron` и `assets/base.ron`, проверяя наличие материала у каждого узла.
- **Самплер**: `create_texture_from_rgba` был `ClampToEdge` + `Nearest` мипы — исправлено на `Repeat` + `Linear`. Мипмап-путь уже был корректен.
- **Геометрия**: `zn_render::geom::make_box` — 24 вершины, раздельные нормали и UV на грань, UV в метрах (`extent / tile_m`), учитывает `scale` и `rotation`. `make_cube` удалён. Попутно исправлен баг: стены арены 50×2×1 рисовались кубиками 1×1×1.
- **Клиент**: текстуры грузятся один раз в `resumed()` в `App::textures`, материалы резолвятся по имени при сборке `render_items`. Сущности: игрок — metal, существо — rust, лут — wood, аномалия — concrete. Текстура не попадает в путь пересборки меша.
- **Редактор**: поля материала и `uv_scale` в инспекторе.

Проверка: fmt чисто, clippy 0 предупреждений, 15 тестов проходят, клиент прожил 20 с с окном и **без предупреждений о текстурах** (все шесть загрузились). Ошибка `connect failed` ожидаема — сервер не был запущен.

### Решения
- Текстуры процедурные, а не скачанные: ноль внешних зависимостей и лицензионных вопросов, легко заменить артефактом.
- UV считаются в метрах, а не 0..1: иначе на стене 50×2 текстура растягивается.
- В `make_box` базис грани подобран так, что `u × v = n` — иначе у граней ±Y был бы обратный обход и отсечение сломало бы пол и потолок.

## Стабилизация: потеря данных, абуз, сессии

Девять коммитов (2f552eb..be89a50) по плану `cosmic-vortex-babbage-2Y_4zSjz.md`.

- **Профиль**: `Player::currency`, `apply_profile()`, общий `spawn_player()` для TCP и UDP. Раньше `level`/`xp` не переносились, и первое сохранение (раз в 60 с) затирало прогресс дефолтами; `save_profile` вдобавок писал `currency = 0`.
- **Экстракция**: XP остался только в симуляции (было двойное начисление), инвентарь сохраняется в БД **до** очистки.
- **Смерть**: `drop_inventory_at()` работает до респауна, лут падает на месте гибели, id из монотонного `next_loot_id` (было `1000+i` с конфликтами). Сервер больше не создаёт лут.
- **Смерть от существ**: `collect_deaths()` вызывается после блока атаки; раньше игрок застревал с 0 HP без респауна.
- **Id-пространства** (`zn_sim::ids`): предметы 1..999, лут 1_000_000+, артефакты 2_000_000+, существа 3_000_000+. Артефакт больше не съедается как аптечка.
- **Валидация**: подбор в радиусе 3 м, проверка origin выстрела (2 м от глаза), лимит кадра `MAX_FRAME_BYTES = 64 КиБ` в `zn-net::read_frame`.
- **Сессии**: `validate_session()` по БД с проверкой `expires_at`, удаление при выходе, очистка раз в 10 минут. Rate limit переехал с username на IP (5 попыток / 5 минут).
- **Клиент**: без токена и кредов — сообщение и `exit(2)` вместо `guest/guest`; yaw/pitch больше не перезатираются каждый снапшот (`correct_angles`, порог ~20°).

Проверка: fmt чисто, clippy 0 предупреждений, **33 теста** (было 15), сервер стартует, миграция 0006 применилась (индексы `idx_sessions_*`, `idx_inventory_user`).

### Решения
- Состоянием владеет симуляция, БД — только сервер: события `GameEvent` несут информацию, но не создают состояние.
- Тесты с sqlite in-memory не заводили — профиль проверяется ручным релогом.

## HUD на egui-wgpu

Шесть коммитов (b70f494..6fdb588), запушены в origin.

- **Рендерер**: `Renderer::render` принимает `Option<UiFrame>` и рисует второй проход поверх сцены (`LoadOp::Load`, без depth). `egui_wgpu::Renderer` живёт в `zn-render`, потому что там device/queue/format; `egui::Context` — в клиенте.
- **HUD** (`crates/zn-client/src/hud.rs`): прицел от `screen_rect().center()`, четыре полосы (HP/RAD/FOOD/WATER), уровень и xp, FPS, инвентарь, полоса экстракции, тосты.
- **Данные**: `xp` добавлен в `PlayerState`; новый `ServerPacket::Inventory` добавлен **в конец** enum (bincode-дискриминанты позиционные). Сервер шлёт инвентарь по UDP после подбора/расхода и после смерти/экстракции (`handle_events` возвращает изменённые инвентари).
- **Статусы**: ошибка логина и обрыв канала показываются тостами; просроченные тосты вычищаются каждый кадр.
- `egui-winit` не подключали: HUD пассивный, ввод в egui не идёт. Понадобится для кнопок.

Проверка: fmt чисто, clippy 0 предупреждений, **37 тестов** (было 33). Клиент прожил 12 с с окном и HUD без паник; единственная ошибка в логе — ожидаемый отказ подключения (он же проверил тост «connection lost»). Визуальную проверку (центр прицела, заполнение полос) делает пользователь.

### Решения
- Второй проход через `forget_lifetime`, `pass` изолирован в блоке: после `forget_lifetime` обращение к энкодеру — ошибка рантайма, а не компиляции.
- Обновления инвентаря идут по UDP даже для TCP-запросов: клиент после авторизации читает только UDP.

## Сборка не соответствовала лаунчеру — и это вскрыло сломанный netcode

Жалоба: лаунчер ставит не то, что в репо. Диагноз по слоям:

1. **Релиз старый** — лаунчер ставит `releases/latest` (v0.1.6), а не текущий код.
2. **В релизе не было `assets/` и `maps/`** — установленная игра рисует заглушку и белые текстуры даже со свежим exe.
3. **Лаунчер запускал игру без `cwd`** — относительные пути ресурсов ломались. Исправлено с двух сторон: клиент ищет ресурсы рядом с exe (`asset_root()`), лаунчер передаёт `cwd`.
4. **CI собирал манифест из всех exe в `target/release`** (включая `zn-gentex`), а выгружал другой список с несуществующим `zn-editor.exe`.

Главный баг: **UDP-протокол не работал совсем**. Клиент слал через `encode` (префикс длины, как в TCP), сервер парсил датаграмму как сырой bincode — Connect/Input/Shots молча отбрасывались. Зеркально сервер слал Welcome/Profile с префиксом, клиент не мог распарсить. Исправлено: UDP = сырой bincode с обеих сторон, префикс только для TCP-фрейминга. Проверено end-to-end: регистрация → сессия → `welcome: player id 2` → `profile: ... level 1`.

Ещё:
- Без кредов клиент заводит `player.txt` рядом с игрой (лаунчер логин не передаёт, Play раньше закрывал игру).
- egui рисуется в не-sRGB view — была двойная гамма.
- v0.1.7 успел выйти сломанным и был удалён; правильная сборка — v0.1.8 (CI публикует по тегу).
- В PowerShell 5.1 нет `[IO.Path]::GetRelativePath` — в CI-скрипте манифеста заменено на `Substring`.

Урок: проверять сетевой слой реальным обменом, а не «компилируется».

## Звук на kira (v0.1.9)

`zn-audio` был пустой структурой, `kira` висела в зависимостях мёртвым грузом — игра молчала.

- Клипы **синтезируются в памяти** при старте, файлов нет (как с текстурами). Детерминированный xorshift с фиксированным seed, поэтому тесты стабильны.
- Шесть звуков: выстрел, попадание, подбор, урон, шаг, смерть. `AudioManager::play(Sfx, gain)` + `distance_gain()` для затухания.
- Нет аудиоустройства → `log::warn` и тишина, игра не падает.
- Клиент: выстрел по клику, шаги при движении по земле (интервал 0.45 с), урон/смерть по падению HP между снапшотами, подбор по росту инвентаря.
- `ShotResult` объявили ещё раньше, но сервер его не слал: `handle_shot` теперь возвращает id существа, оба транспорта отправляют ответ — из него клиент берёт звук попадания.

Проверка: 41 тест (было 37), clippy чистый, устройство открывается без ошибок.
